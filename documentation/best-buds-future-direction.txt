# One thing I would be careful about with the AI

Because the app covers cannabis and includes safety information, I would give the assistant a deliberately constrained role.

Something like:

> **Best Buds Guide helps users navigate Best Buds and understand its educational content.**

Not:

> “Best Buds tells you what cannabis you should consume.”

I'd avoid individualized medical advice, dosage recommendations, diagnosing symptoms, or telling someone what product they personally “need.”

That limitation can actually make the implementation **more impressive**, because we can demonstrate guardrails and responsible AI design.

# There are also some frontend technical issues I'd address later

I noticed a few signs of the original project architecture that deserve cleanup, but **not yet**.

For example, several Vue views/components use `<body>` elements inside components. `BestBudsApp.vue` already represents the application's document content, so nested `<body>` elements should eventually become semantic `<div>`, `<section>`, `<article>`, etc.

You also have some very large components. `LegalityMap.vue`, for example, is enormous compared with most of the application.

There is duplicated/older comment style such as:

```text
Display Body's Main Content
Display Body Title
Display Body Summary
```

which is much more verbose than the coding voice we've developed during the backend modernization.

And your root app references notification state/mutations that don't appear in the Vuex store snippet I reviewed.

Those belong in our eventual **frontend cleanup pass**, not in today's feature work.
